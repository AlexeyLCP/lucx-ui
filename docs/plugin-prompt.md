# Базовый промт: написать плагин для LucX-UI

Готовый prompt-шаблон для нейросети (Devin, ChatGPT, Claude). Скопируй блок
ниже, допиши свою задачу в `<ЗАДАЧА ПЛАГИНА>` и вставь в ИИ. Полный контракт
и ревью-промт: [plugin-sidecars.md](plugin-sidecars.md).

```text
Ты пишешь плагин для панели LucX-UI (форк 3x-ui) в формате sidecar.
Правила контракта плагина, нарушать нельзя:

1. Доставка: один ZIP. В корне архива manifest.json с полями:
   id — латиница в нижнем регистре, цифры, "-", "_", до 64 символов, не с "-"/_;
   name — человекочитаемое имя;
   version — семвер;
   apiVersion: 1 (ровно один);
   type: "sidecar" (ровно это значение);
   entrypoint — ОТНОСИТЕЛЬНЫЙ путь до исполняемого файла внутри архива,
   без ".." и не абсолютный;
   architectures: [] для скриптов (архитектуронезависим) или список GOARCH,
   который реально собран ("amd64", "arm64" и т.п.);
   permissions: {"network": [], "panelApi": [], "bot": []} — пока декларация
   намерений, панель её не форсит.
2. Плагин — отдельный процесс. Панель даёт ТОЛЬКО три переменные окружения:
   LUCX_PLUGIN_ID, LUCX_PLUGIN_VERSION, LUCX_PLUGIN_DATA.
   LUCX_PLUGIN_DATA — приватная папка на запись: весь mutable state
   (конфиги, базы, кэш) держи только там. Ничего не пиши вне своей папки.
3. Доступа к API панели, базе данных, токенам Telegram-бота и подпискам НЕТ.
   Не используй их и не пытайся читать файлы панели — таких путей в
   контракте не существует.
4. Логи — только stdout/stderr, панель пишет их в plugin.log. Пиши
   осмысленные строки с таймстампами: старт, конфиг, ошибки, стоп.
   Секреты и длинные дампы в лог не сливай.
5. Жизненный цикл: при Stop панель шлёт SIGINT и через 3 секунды SIGKILL.
   Обработай SIGINT/SIGTERM и завершайся чисто (закрой сокеты, сли файлы).
6. Авто-рестарта нет: упал — лежит до ручного запуска из панели. Значит,
   процесс должен сам жить постоянно (сервисный цикл), а код должен быть
   простым и не падать на пустых входных данных.
7. Порты: слушай порт из конфига/переменной окружения с безопасным
   дефолтом, в лог печатай, на чём слушаешь, чтобы оператор видел конфликты.

ЗАДАЧА ПЛАГИНА:
<ЗАДАЧА ПЛАГИНА: что делает, что слушает, какие порты, что хранит в
LUCX_PLUGIN_DATA>

Выдай результат ровно в таком составе:
(1) manifest.json — готовый файл;
(2) код плагина: shell-скрипт со строкой #! ИЛИ статичный Go-бинарь
    (сборка: CGO_ENABLED=0 GOOS=linux GOARCH=<arch> go build -trimpath
    -ldflags="-s -w") + при необходимости go.mod;
(3) команда сборки ZIP: zip -r <id>.zip manifest.json <остальные файлы>;
(4) локальная проверка: как запустить вручную с выставленными
    LUCX_PLUGIN_* , какая строка ожидается в логе на старте, и как
    проверить чистое завершение по SIGINT (kill -INT <pid>).
Никаких пояснений сверх этого списка — только артефакты и шаги проверки.
```

Мини-плагин для Smoke-теста контракта (shell, без тулчейна) — в
